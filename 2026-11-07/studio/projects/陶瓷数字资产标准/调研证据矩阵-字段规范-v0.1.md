# 调研证据矩阵 字段规范 v0.1

> 配套文件：`调研证据矩阵-v0.1.xlsx`（同目录，已按本规范生成并填入报告 v0.5 全部条目）。
> 编制：2026-10-29｜定位：**面向 AI 拆解的调研证据矩阵**，同时是阶段性汇报的证据底座。
> **保密**：标准未发布。本矩阵含企业实名与「白纸供稿·来源待补」数字——项目内部使用，不外传、不上传、不公开引用；对外只发白纸审过的内容。

## 1. 定位与行单位

本矩阵的本质不是「资料汇总表」，而是**证据矩阵**：一行对应一个可独立识别的**数字化实践/案例/政策/标准条目**，字段尽量可枚举、少歧义，AI 从链接文本中抽取时才能横向可比，汇报时才能快速筛出「广东缺什么、谁最接近」。

- 同一对象有多个独立实践时拆成多行（例：蒙娜丽莎的 APS→MES 体系与智能仿版各一行）。
- **产区画像、端到端流程、介入物方案三类内容装不进矩阵行单位**（硬塞会让全表充满「不明确」，毁掉横向可比），在 xlsx 中另设三张底表承接：产业分布底表（报告第一部分）、流程与断点底表（报告第二部分）、介入物与试点（报告 §2 介入物＋第四部分）。

## 2. 主表字段字典（五模块 28 字段）

### 一、对象识别

| 字段 | 填写说明 / 取值 |
| --- | --- |
| 编号 | `GD-CER-001` 起，便于引用 |
| 调研对象名称 | 企业/平台/政策/标准/研究项目/机构名称；同一企业多个实践在名称后加括号注明实践 |
| 条目性质 | 企业／产区或产业集群／产业平台／政策文件／标准规范／研究项目／设计机构／园区或协会／其他 |
| 细分领域 | 建筑陶瓷／卫生陶瓷／日用陶瓷／工业与电子陶瓷／艺术陶瓷／陶瓷装备／色釉料／设计服务／产业平台／文创空间／其他 |
| 所在地（市/镇） | 自由文本，写到「市+镇」粒度（报告的工作粒度在镇：枫溪/古巷/南庄/源潭） |
| 信源类型 | 官网／新闻报道／政策文件／学术论文／企业公告／标准文本／访谈／行业白皮书／白纸供稿 |
| 来源编号 | 报告 S1–S78 体系编号；无编号填「design.md §x」或「正文内链」 |
| 来源链接 | 原始 URL；多个用「；」分隔；没有写「（见分轮 note）」 |
| 来源日期 | 发布或更新日期 YYYY-MM-DD，可写区间 |
| 访问日期 | 精确日期；报告调研期统一记录的写「2026-10-22～29（报告调研期）」 |

### 二、数字化实践

| 字段 | 填写说明 / 取值 |
| --- | --- |
| 实践主题（一句话） | 如「AI 质检与全工序追溯」「花纸—成瓷纸质单据闭环」 |
| 实践阶段 | 概念／试点／已落地／规模化 |
| 涉及环节（多选） | 研发设计／**设计—制造交接**／生产制造／质检／供应链／交付服务／营销展示／数据平台 |
| 关键技术或方法（多选） | AI与机器视觉／数字孪生／标识解析／知识图谱／BIM／参数化建模／数据中台／其他（括号注明） |
| 数据标准化程度 | 有公开数据标准／有内部属性模板／仅有系统接口／仅内部系统／**纸质或人工**／不明确 |
| 产品数据对外输出 | 有／无／不明确；填「有」时括号注明输出对象（设计端/采购方/平台等） |

### 三、与设计应用的关联（核心）

| 字段 | 填写说明 / 取值 |
| --- | --- |
| 是否直接服务设计端 | 直接／间接／否／不明确 |
| 设计端数据类型（多选） | 几何模型／纹样图像／参数表／工艺知识／性能数据／环境数据／服务流程数据／其他 |
| 设计工具可调用性 | 可直接调用／需转换／不可调用／不明确；不限定 BIM，注明工具类型 |
| 资产许可或授权 | 有明确许可／有申请流程／无／不明确 |
| 版本管理或追溯 | 有／无／不明确；填「有」时括号注明追溯对象（产品/纹样/工艺记录等） |

### 四、证据与缺口

| 字段 | 填写说明 / 取值 |
| --- | --- |
| 证据等级 | **核实／部分核实／待核实／白纸供稿·来源待补**（沿用报告口径，白纸 2026-10-29 确认；不用强/中/弱） |
| 缺失信息（多选） | 字段定义／许可细则／对外接口／设计验证／工艺审核／交付记录／版本机制／其他 |

## 3. 本轮对白纸原设计的修订（AI 提案，已并入 v0.1）

| # | 修订 | 理由 |
| --- | --- | --- |
| 1 | 细分领域补：日用陶瓷、工业与电子陶瓷、色釉料、文创空间 | 原枚举漏了试点第一优先（日用）和工业线整块（三环/微容）；色釉料是报告认定的独立控制环节 |
| 2 | 涉及环节加「设计—制造交接」 | 这是整个项目的横贯抓手（设计版本↔批次关联四产业全未打通）；该列填出来预期几乎全为「否/不明确」——「涉及交接的条目数≈0」本身就是汇报里最有力的一张图 |
| 3 | 条目性质加「产区或产业集群」 | 枫溪单据链、古巷代工群是产区级条目，原枚举无处安放 |
| 4 | 数据标准化程度加「纸质或人工」 | 枫溪纸链是五产业唯一完整「批次↔工单↔物料」手工体系，不填就无法归类 |
| 5 | 信源类型加「行业白皮书」「白纸供稿」 | 企丞出海白皮书、白纸两份供稿 |
| 6 | 证据等级沿用报告四档＋来源编号列 | 避免与报告 S1–S78 双轨对不上账 |
| 7 | 对应规范关注点加「复核层」 | 原五层装不下六字段的「质量（完整准确/可追溯可复核）」 |
| 8 | 所在地改自由文本「市+镇」 | 市级枚举会把罗定微容挤到「其他」 |
| 9 | 一句话结论列：报告原句预填＋「AI 草稿」标记 | 遵守白纸 10-03「数据先行」：AI 摘录不发明解读 |

## 4. 填写规则

1. 枚举列从「枚举值」表取值，多选用「；」分隔；取不到填「其他」并在备注说明。
2. 无法确认填「不明确」，**不留空、不推测**。
3. 日期统一 YYYY-MM-DD；可写区间或「待补证」。
4. 「一句话结论」汇报前由白纸定稿；「AI 草稿」标记的条目尤其要过。
5. 「待追问问题」写清向谁、问什么、要什么材料——这列直接长成下一轮访谈/材料申请清单。
6. 新增枚举值先加「枚举值」表，再用于主表（数据验证的唯一取值来源）。

## 5. AI 拆解提示词（发链接时整段复制）

```
请从以下文本/链接中抽取信息，严格按给定表头输出 CSV（UTF-8，逗号分隔，字段内逗号改为「；」）。
一行对应一个可独立识别的数字化实践/案例/政策/标准条目；同一对象有多个独立实践时拆成多行。
取值优先使用「枚举值」表中的枚举值；无法确认的填「不明确」，不要留空，不要推测。
证据等级只用四档：核实/部分核实/待核实/白纸供稿·来源待补。
「设计端数据类型」「设计工具可调用性」不限于 BIM，根据文本中提到的任何设计工具、平台或流程判断。
多选字段的值用「；」分隔；日期用 YYYY-MM-DD；所在地写到「市+镇」粒度。
「一句话结论」列：文本中有对应缺口句则原句摘入并标注出处章节，没有则填「AI 草稿：<一句合成>」。
每个判断尽量在备注附一句原文依据或页码/段落位置。
如文本自带来源编号（Sxx）请填入来源编号列；没有则留空。
```

## 6. 汇报三视图（不贴整表，按视图筛）

1. **现状视图**：按「涉及环节」×「数据标准化程度」做数据透视，看广东实践集中在制造端还是设计/交付端。
2. **缺口视图**：筛「是否直接服务设计端＝直接」且「数据标准化程度＝有公开数据标准」的条目数（预期≈0，即缺口本身）；再筛「缺失信息」含「字段定义/许可细则/对外接口」的条目形成缺口清单。
3. **优先级视图**：按 P0/P1 分组，每组配「待追问问题」，直接作为下一轮访谈或材料申请清单。
