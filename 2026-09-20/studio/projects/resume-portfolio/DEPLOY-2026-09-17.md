## 二、上线（两选一，推荐 A）

### A. 连 GitHub 仓库（推荐：以后 `git push` 自动发布）

1. 打开 https://dash.cloudflare.com/ ，注册/登录（邮箱即可，免费档够用）
2. 左侧 **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
3. 授权 GitHub，选仓库 **`baizhichen-web/personal-website`**（独立发布仓库，2026-09-17 建；工作空间仍是编辑源，改动经它同步推送）
   - 仓库是私有的，Cloudflare 会装一个 GitHub App 来读——只有该仓库的读权限
   - 仓库里只有网站文件（不含工作空间笔记与凭据）
4. 构建配置（**这一页最关键，逐字照填**）：

   | 项 | 填什么 |
   | --- | --- |
   | 生产分支 | `main` |
   | Framework preset | `None` |
   | **Root directory**（展开 advanced 才看得到） | **留空**（仓库根即站点根；此处曾是工作空间仓库路径，已过时） |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | 环境变量 `NODE_VERSION` | `22.18.0`（固定住，避免托管方默认版本漂移） |

5. **Save and Deploy**，等 1–3 分钟

### B. 本地直接上传（不走 Git，改一次传一次）

需要先在终端登录（会弹浏览器让你点授权）：

```bash
cd studio/projects/resume-portfolio/web
npm run build
npx wrangler pages deploy dist --project-name=baizhichen-site
```

第一次会让你登录并创建项目；之后每次改动都要重跑这两条。

## 三、部署后必做一步：填 SITE_URL 并重建

站点里有几处要写死正式域名（AI 副本里的链接、结构化数据、sitemap）。**域名只有部署完才知道**，所以：

1. 部署成功后，Pages 会给你一个域名，形如 `https://<项目名>.pages.dev`
2. 回到 Pages → 你的项目 → **Settings → Environment variables**，加一条：

   | 变量名 | 值 |
   | --- | --- |
   | `SITE_URL` | `https://<你的域名>`（末尾不要斜杠） |

3. 触发一次重新部署（A 方案：随便改一个文件 push，或点 **Retry deployment**）
4. 重建后 `sitemap.xml` 会**出现**（空域名时不产出——给爬虫半截地址不如不给）

## 六、本次为上线排掉的坑（免得下次又踩）

- 生成器原先直接 `import` 一个 `.ts` 文件 → 依赖 Node 的类型剥离（22.18+ 才默认开），
  CI 上 Node 旧一点就构建失败。已把那份数据搬成 `.mjs`，两侧都能直接读。
- `prebuild` 会抓 GitHub 热区图，CI 里没有 `gh` 命令会失败——但它本来就是 best-effort
  （失败打警告、沿用提交里的快照），**不会阻塞构建**。也就是说线上热区用的是最后一次
  在本地构建时抓到的数据；要更新就在本地构建一次并提交 `src/data/githubHeatmap.json`。
