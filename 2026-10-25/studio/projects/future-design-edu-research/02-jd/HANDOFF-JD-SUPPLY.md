## ⭐ 最省事的方式（2026-10-03 起，推荐）：直接贴进对话

**把 JD 原文直接粘贴到对话里**，原样复制、不用整理。下面的文件格式要求是给"你直接往目录里放文件"这条路用的；走对话投料时，格式加工（YAML 头、命名、归档）全部由我来做。

每条 JD 尽量带上（缺了我会问或标"未知"，不会卡住）：

1. **公司名 + 岗位名**（没有就从正文猜，标注猜测）
2. **URL**（有的话；没有就算了）
3. **发布/更新日期**（页面上有就顺手抄一下）
4. **正文**——原样，不要删减；套话句子也要，我要靠它们建套话词表

一次贴一条或十几条一起都行。我从对话里收到后：归档进 `jd-raw/manual-cn|manual-sme/` → 重建索引 → 重跑门槛统计 → 并入能力项编码 → 出国内/海外对比表。

**能贴 URL 的场景**：企业官网等公开页（我可以自己抓）。**必须贴正文的场景**：BOSS 直聘、智联、拉勾这类登录墙后的页面——你浏览器里能看、我抓不到，这正是你投料不可替代的地方。

## 格式要求：每条一个文件夹对

**最省事的做法**——一个 JD 一个 `.md` 文件，YAML 头 + 正文：

```markdown
---
source_name: 联想
tier: manual-cn
job_id: 2359
title: "硬件产品经理"
department: "IDG深圳"
location: "深圳"
url: https://talent.lenovo.com.cn/position/detail?id=2359
updated_at: 2026-09-28
fetched_at: 2026-10-01
---

# 硬件产品经理

（把 JD 正文原样粘在这里，岗位职责、任职要求、加分项都要，格式不用整理）
```

放进 `02-jd/jd-raw/manual/` 即可。**注意：索引脚本只认 `.json`**——如果你只放了 `.md`，交给 AI 时说一声，由 AI 补建同名 `.json`（2026-10-03 实测：只放 md 不会被索引进统计）。走"直接贴对话"路径则完全不用管这些。

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `source_name` | ✓ | 公司名 |
| `tier` | ✓ | **这个字段就是分层统计用的，不能乱填**。国内分三层（2026-10-03 起）：`manual-cn`=国内大厂/上市企业；`manual-sme`=传统制造/硬件/中小企业；`manual-ai`=国内 AI 原生创业公司（与海外 AI 语料最可比的一层，SKG 那种硬件企业**不**放这层）。拿不准就贴对话时说清公司业务，AI 来标 |
| `job_id` | ✓ | 没有就写日期+序号，如 `20261001-01` |
| `title` / `location` / `url` | ✓ | |
| `updated_at` | 尽量 | 职位发布或更新日期。**没有就写抓取日期，并在报告局限里注明** |
| `fetched_at` | ✓ | 你复制下来的日期，格式 `2026-10-01` |

正文里**不要**做删减和整理——JD 的原始措辞是分析对象，尤其是那些看起来像套话的句子，我要靠它们建套话词表。
