## 这条线为什么值得做

三条线里**只有这条带时间序列证据**。

- 单看 2026 年的培养方案，只能说"现在是这样"——横截面
- 对比 2015 / 2020 年的，能说"**新增了什么、消失了什么**"
- **某门课从培养方案里消失 = 市场不再认它**。这是横截面研究做不到的推论

而且它同时解决两件事：

1. **给"新"提供可复现的定义。** design-jd.md §2 说"新 = 雇主现在要 + 学院过去不教"，那条"过去不教"只能靠访谈和回忆，属于弱证据。培养方案的纵向对比把它变成**有日期的硬证据**。
2. **它是国内语境唯一能自动化的线。** JD 线在国内抓不动（腾讯接口 404、104 JS 渲染、职友集登录墙），但高校培养方案大量是**公开 PDF 或静态网页**，可抓可存档。

## 采集方法

### 当前版（好办）

- 研究生培养方案 PDF：学院官网 → 研究生教育 → 培养方案 / 学位授予工作
- 招生专业目录：研究生院网站，通常含课程清单与学分
- 本科培养方案：如果要对比"设计专业"整体，也要收

### 历史版（关键难点）

**官网只挂最新版，历史版在 Wayback Machine。** 这是本线的核心技巧。

> ⚠️ **本机实测：`web.archive.org` 直连不通（HTTP 000），必须走本地代理 `127.0.0.1:7897`。**
> ```
> curl -s -x http://127.0.0.1:7897 "http://web.archive.org/cdx/search/cdx?..."
> ```
> 另外 Internet Archive 偶发整体离线（返回 "Temporarily Offline" 页面），**失败时先重试 2–3 次再判定不可用**——实测第一次失败、隔几秒重试就正常了。

```bash
# 先问"这个 URL 有没有存档、离我想要的日期多近"（单点查询，最常用）
curl -s -x http://127.0.0.1:7897 "http://archive.org/wayback/available?url=example.com&timestamp=2018"

# 列出某页面的所有历史快照时间点（筛选多个快照时用）
curl -s -x http://127.0.0.1:7897 "http://web.archive.org/cdx/search/cdx?url=example.edu.cn/*&output=json&from=2014&to=2021&limit=50&collapse=urlkey"

# 直接取某个时间点的快照
curl -L -x http://127.0.0.1:7897 "https://web.archive.org/web/2018/https://example.edu.cn/..." -o snapshot.html
```

**操作要点：**

1. 先用 `archive.org/wayback/available` 快速判断某页有没有存档，再决定要不要上 CDX
2. **不要盲目试年份**——用 CDX 列出实际存在的快照时间点
3. 快照可能是**旧版域名**、旧版路径，或挂在 PDF 直链上——CDX 查询要多试几种 URL 模式，用 `collapse=urlkey` 避免重复
4. **每个快照都要记 `web.archive.org` 的完整 URL 和快照日期**，这是本线唯一的原始出处
5. 页面结构常在多年间改版，**解析规则要按年份分别写**，别指望一套规则通吃
6. 有些学校把培养方案改成了需要登录的教务系统——这类放弃，在附录里注明"无法获取"，**不要用推测填补**

## 对比维度（= 交叉矩阵的行）

从每份培养方案提取：

| 字段 | 说明 | 为什么 |
|---|---|---|
| `模块名称` | 原文课程名，不翻译不改写 | 名称变化本身就是信号 |
| `领域` | 设计 / 工程 / 人文 / 商业 / 计算机 / AI | 看学科配比 |
| `学分或学时` | 用于算占比 | 看权重 |
| `类型` | 必修 / 选修 / 工作坊 / 实习学分 | 看定位 |
| `教学形式` | 讲授 / 项目制 / 动手做 | 对应 JD 里的 D1/D2 |
| `首次出现年份` | **本线最重要的字段** | 判断"新" |
| `来源` | 文件名 + URL + 快照日期 | 可追溯 |

## 待验证的变化假设（别当结论）

这几条是**假设**，需要用数据证伪或证实。列在这里是为了让你知道要盯什么：

- **模块名更替**：「交互设计」→「产品设计」→「设计工程 / Design Engineering」
- **增设 AI 类模块**：「AI 与设计」「生成式设计」「人机协同设计」
- **增设非设计课**：编程、数据科学、机器学习、系统工程——**占比是多少？**
- **"设计系统"从选修变必修**（对应 JD 里 Design Systems 已是独立岗位族）
- **无障碍设计独立成课**（对应 OpenAI 有独立 Product Designer, Accessibility 岗）
- **行业垂直方向出现**：医疗 / 可持续 / 公共部门 / AI 治理（对应 JD 里 FDE 按行业分垂类）
- **企业合作与实习学分化**
- **反向的**：手绘、软件操作、传统媒介类课程是否在删减

**特别提醒最后一条。** 只收集"新增了什么"会让报告变成唱多。**被删掉的课程信息量往往更大**，务必两个方向都记。

## 陷阱

1. **"新设专业"的宣传稿 ≠ 进了培养方案。** 校领导说新设了方向，可能只是招研究生但课程还是老的。**必须以方案原文为准。**
2. **模块名换了但内容没换。** 「交互设计」改名「体验设计」，内容没变。名称变化单独不算证据。
3. **不同学校的"学分"不可直接比**（学分数制不同、有的按学时）。**占比只在同一学校内部做纵向比较**，跨校只比结构不比数值。
4. **别只找现成的对比文章。** 网上有"中外设计教育比较"这类二手综述，可用作线索，**但必须回到各校方案原文核对**——这类二手综述的年代往往很旧。

## 附：抓 Wayback 快照的实测口径（2026-10-04 补，已验证）

**通道**：本机 `curl.exe` 的 https 走 schannel 会全部返回 000（CDX 查询也一样）。所以 CDX 查询与快照抓取**都必须用 `http://` + 代理 127.0.0.1:7897**。

**实测可用的抓快照命令**（`id_` 后缀 = 取原始内容，而非 Wayback 自己的包装页）：

```
& curl.exe -s -L -x http://127.0.0.1:7897 --max-time 90 -A "Mozilla/5.0 (research; academic citation)" \
  "http://web.archive.org/web/<时间戳>id_/<原始URL>" -o <本地文件>
```

实测记录：上海交大 `designschool.sjtu.edu.cn` 的 `20241027123632` 快照成功落盘（28,110 字节）。

**⚠️ 踩到的坑：SPA 站点的快照 HTML 没有正文。** 上述 28KB 文件里「培养方案 / 课程 / 学分」**零命中**——
该站内容由 JS 异步加载，存档只存了空壳。对这类站点，历史版要抓的是 CDX 里的**文档文件**（PDF / DOC / XLSX），不是 HTML 页面：

```
& curl.exe -s -x http://127.0.0.1:7897 "http://web.archive.org/cdx/search/cdx?url=<domain>&matchType=domain&output=json&filter=mimetype:application/pdf&collapse=urlkey&limit=200"
```

**判据**：抓下来的文件要先 grep 一次关键词（培养方案/课程/学分 或 Course/Credit），**零命中就判定「快照不可用」，不要当成拿到了历史版**。

### 附二：三条抓取通道的实测边界（2026-10-04 复核）

| 通道 | 国际站 | 国内站 | 二进制 PDF | 备注 |
|---|---|---|---|---|
| `web_fetch` 工具 | ✅（aalto.fi 200 / 80KB） | ❌（grs.zju.edu.cn 报 fetch failed） | 仅文本 | 最省事，优先用 |
| `run_code` 内 Node 原生 `fetch` | ✅（aalto 200、design.cmu.edu 200） | ❌（grs.zju.edu.cn 在我这边同样 failed） | ✅ 可取 arrayBuffer | **抓 PDF 原件用它** |
| `curl.exe` | ❌ https 全 000（schannel） | 同 | 仅 http 可用 | 只用于 http:// + Wayback |

**⚠️ 一处未复现的分歧（如实记录）**：清华/浙大组报告「Node fetch 能抓 grs.zju.edu.cn」，但我在主会话复核时该站 Node fetch 与 web_fetch 均失败；
不过它落盘的 `grs.zju.edu.cn-附件PDF-1a1a0bbd.pdf`(258KB) 与 `cst.zju.edu.cn-附件PDF-67d99852.pdf`(10.9MB) **魔数确为 `%PDF`、确是真件**。
结论：文件是真的，但「Node fetch 对该站的稳定性」存疑——重抓失败时先重试，不要立刻判定站点不可达。

**另**：清华官方「研究生培养方案汇编」PDF 在 `cloud.tsinghua.edu.cn/seafhttp/...`，直链返回 **403 Access token not found**（需分享会话 token），且该域在 Wayback **0 条存档**——属「不绕登录态」红线，只能改走研究生院站内与 yzbm 招生专业目录。
