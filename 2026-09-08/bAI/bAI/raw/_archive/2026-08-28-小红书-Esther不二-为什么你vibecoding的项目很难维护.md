# 为什么你 vibecoding 的项目很难维护｜长教程 - Esther不二

> 白纸转发（2026-08-28），附平台整理的视频要点与逐字稿。AI Designing 簇第 6 号成员。

## 视频要点总结（平台整理）

这是一期关于 Vibe Coding 项目可维护性的前端入门教程，主要讲了为什么 AI 生成的项目容易越写越难维护，以及如何用现代前端工具链去规避。

1. **为什么纯 HTML 项目难维护**：小项目用纯 HTML 还行，但规模一上来，所有结构、样式、逻辑混在一个文件里，动辄几千行代码，改一处牵一发而动全身，后期维护非常痛苦。
2. **网页的三大组成部分**：HTML（骨架/结构）、CSS（样式）、JS（逻辑）。Vibe Coding 时 AI 默认给你"全塞进 HTML"，看起来很全，但改不动。
3. **前端框架解决什么问题**：React/Vue 的核心作用是模块化——把页面拆成独立组件，各有自己的结构、样式和逻辑，互不干扰，类似搭积木。比喻：不用框架就像一个人包办奶茶店点单、制作、叫号所有流程；有了框架就像拥有一套现成的流水线规则，各司其职。
4. **Vite + TypeScript + npm 的作用**：Vite 快速搭建项目、自动配好目录结构和依赖；TypeScript 加类型声明让代码更严格更安全、AI 也更容易维护；npm 是前端代码的"应用商店"。
5. **实操演示**：npm create vite@latest → 选 React + TypeScript 模板 → 标准项目结构（src/、App.tsx、样式拆分、package.json）→ 手写 Header 组件演示"拆模块 → 引入 → 渲染"。
6. **Vibe Coding 最佳实践**：
   - 一开始就明确告诉 AI：用 React 或 Vue + TypeScript 来写，要一个可长期维护的项目
   - 推荐让 AI 学习开源的 React Practice 最佳实践清单，规避常见坑
   - 已有的纯 HTML 项目，不要继续往上堆，尽早重构
   - 目录命名用英文，模块命名清晰，组件之间尽量减少耦合
