# refactoring-ui-skill（Refactoring UI 设计工艺规则）

## 一句话总结

把《Refactoring UI》全书蒸馏成「值只能从档位里选」的机械规则：间距/字号/字重/灰阶/阴影五档尺度 + 层级技术（字重与颜色做层级、弱化做强调）+ 九条硬规则 + 30 行症状→修法诊断表——**管「怎么做好」，不管「我们长什么样」**。

## 关键摘录

> 业余感 UI 的最大根源是随手拍值——这里 17px、那里 #3B82F6、悬停态 lighten(5%)。永远从尺度里设计。

> 层级靠字重与颜色做，不靠字号。当主角怎么都不突出时，别加码主角——去削弱与它竞争的配角。

> 阴影按「元素在 z 轴离用户多近」选，不按「哪个好看」选。

> 彩色底上永远不放灰字（灰底白字显脏）；删除键不该是大红钮——红钮留给确认弹窗里它真正是主行动的时刻。

## 结构（五件）

1. **SKILL.md**：尺度系统（间距/字号/字重/颜色/阴影/行宽/圆角）+ 工作流程七条（⚠️ 不采纳，流程归 VIBE-DESIGNING 1.3）+ 层级技术 + 九条硬规则
2. **systems.md**：从零建色板方法论（定 500 → 两端 → 填中间；HSL 思维；保饱和；暗色模式）——**白纸将来拍板色调时的操作手册**
3. **techniques.md**：手艺十节（模拟光源/双影/基线对齐/字距/选字体/打破默认形状）
4. **diagnose.md**：30 行症状→修法对照表（「看起来乱=没层级」「业余感=浏览器默认」）——**验收段与「哪里不对劲」时的查表**
5. **tokens.css**：对比度验证过的起步令牌（含语义角色层+暗色模式）——⚠️ 自带现成审美值，只作参照不作默认
