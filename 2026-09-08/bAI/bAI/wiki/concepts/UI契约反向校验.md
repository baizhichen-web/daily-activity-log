# UI契约反向校验

## 定义

支撑 UI/UX 的契约层（领域建模、数据结构、API、状态变更）**必须接受 UI/UX 验收的反向校验**，而不是开工前不可动摇的终点；必要时优先实现最小可用的 UI/UX 做真实端到端验收，接受反馈随时调整契约层。

背景判断：AI 是系统工程师不是交互工程师——倾向端到端先铺契约、以"是否破坏契约"判断 UI 正确性；但好的 UI 必然反复推敲，推敲必然改逻辑，所以契约层要**为快速变更而设计**（可替换、可降级），并从验收者角度层层递进安排步骤。

适用边界：重 UI 交互应用；纯内容展示/轻量交互不适用（渐进式增强反而更慢——速度与质量的权衡）。
