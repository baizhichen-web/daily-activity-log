## 2026-08-28 升级 1.0.61 → 1.0.91 破坏性变更

1. **连字符子命令移除**：`lark-cli base record-list` 报 unknown subcommand，一律用 `+shortcut` 形态（`+record-list` / `+record-upsert` 等）。
2. **`+record-batch-create --json` 结构变更**：旧 `{"fields":[...],"rows":[[...]]}` → 新 `{"create_records":[{字段名:值,...}]}`（每条记录一个字段映射；单选字段值用数组如 `["待确认"]`）。旧结构会被原样透传给 API 导致写入失败。已同步修复 `ops/scripts/daily-scan-push.mjs`、`daily-event-scan.mjs`。
3. **`docs +update --command str_replace` 参数变更**：`--old/--new` → `--pattern`（匹配文本）+ `--content`（替换内容）。
4. **`+record-search --filter-json` 结构变更**：旧 `{"conjunction","conditions":[{"field_name","operator","value"}]}` → 新 `{"logic":"and","conditions":[["字段","==",值]]}`。
5. **`+record-list` 输出**：默认 markdown 表格；`--format json` 为矩阵结构 `data.data`（行数组）+ `data.record_id_list`，新增 `--format ndjson --output <file>` 供分析落盘；`_record_id` 是元数据不是表格字段（只进 record_id_list）。
6. **不变项**：`--as user` / `--as bot` 身份参数照旧；`+record-upsert --json` 字段映射照旧；`--dry-run` / `--jq` 照旧。
7. 已废弃组件未改：`ops/bridge`（2026-08-17 归档）的 system prompt 与 erato 提示词仍含旧 `fields/rows` 与旧 filter 结构，如未来复活 bridge 需先改。

## 补授权流程（如未来再加 scope，lark-shared skill 的 split-flow）

1. `lark-cli auth login --scope "<scope>" --no-wait --json`（或 `--domain all`）拿 `verification_url` + `device_code`
2. 把 URL 交给用户完成授权（需生成二维码展示）
3. `lark-cli auth login --device-code <device_code>` 完成登录

无 lark-cli 时的兜底读法：本地快照 `ops/reports/board-snapshot.md`

## 相关环境坑（顺带记忆）

- 本机 npm.ps1 被 PowerShell 执行策略挡住：用 `node <npm-cli.js>` 或 .cmd 入口绕行
- 判断"文件不存在"前先确认是权限问题还是真缺失：用 `Test-Path <具体路径>`，不要依赖目录列举
