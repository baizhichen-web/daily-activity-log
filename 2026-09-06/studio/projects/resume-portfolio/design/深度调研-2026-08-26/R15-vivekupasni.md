# R-15 vivekupasni.in — 深度调研档案

> 调研：2026-08-26 · chrome-devtools 实测
> 一句话：米色文档流 + 斜体状态标签（latest / archived）——"生长型简历"的界面语言出处。

## 1. 加载方式与技术栈
- 轻量静态站：外链脚本 10 + 内联 15KB、1 stylesheet（11KB）、SF Pro Display 单字体、图片仅 2 张。
- **零 CSS 动效**（keyframes=0、hover 规则=0）——纯文档流。
- 米色底 rgb(241,240,239)，页面总长 1182px（约 1.75 屏）。

## 2. 设计巧思与组件
- **状态标注体系（本站核心巧思）**：每段经历/项目尾部带斜体状态标签——
  - 「independent · software developer **(latest)**」
  - 「cluezy · product builder **(archived)**」
  - 一眼区分"现在进行的事"与"已完成的事"——简历从静态清单变成**带版本状态的数据库记录**。
- 小写标题（"i'm vivek upasani"）延续非正式语气流派。

## 3. 网页内容
Product-focused full stack developer。结构：名字+一句话（"ships fast and focuses on user experience"）→ 经历/项目混排列表（每条：主体 · 角色 (状态) + 两句描述）→ 技术栈/链接。9 个链接，无图片展示区。

## 4. 交互
- 无。内容即界面，滚动即全部。
- （对照：它的"交互"发生在**内容层**——状态标签随真实项目状态手动更新。）

## 5. 对我们的启示
- **取**：**状态标注体系直接采用**——我们的 Writing/Work/Education 列表已计划 latest/archived 标注（G-17 的一部分），本站是原始出处；**经历与项目混排单列表**（不分区，按时间线统一流）值得对比我们"三列表分区"的选择；米色纸感底色（与我们暖纸白 #FAFAF7 同族，佐证色彩方向）。
- **不取**：内容密度过低（每条仅两句，无证据链接）；零视觉记忆点。
- **句式沉淀**：「主体 · 角色 (状态)」+ 两句职责描述 = 最小可读经历条目格式。
