## 1. 目标与现状

**现状**：翻页书 MVP 已上线（首页海报墙 / 简历页 / 联系页，双语+黑夜模式）。项目详情目前只是海报展开后的一段占位正文（`fb-poster-details`），**没有真正的项目页**。

**目标**
| # | 目标 | 检验 |
|---|---|---|
| G1 | 项目内容由白纸在可视化界面里排版（图/文/视频），无需改代码 | 试点：白纸独立完成一个项目的录入 |
| G2 | AI 能在同一份内容上做版式精修（层级、间距、图注、节奏） | 精修后 diff 可读、可回退 |
| G3 | 长文有目录、有锚点、有站内跳转；跳转有过渡动效 | 简历 §4 点项目 → 项目页；目录高亮正确 |
| G4 | 版式与既有设计体系同源（tokens/衬线文档流/发丝线/暗色） | 与简历页并排目检一致 |
| G5 | 图文视频混合，媒体不拖垮仓库与加载 | 单页首屏 ≤ 1.5s（本地）；仓库媒体增量可控 |

**非目标（本期不做）**：评论、站内搜索、多作者协作、云端后台、en 全文翻译（沿用最低覆盖策略）。

## 2. 内容模型

### 2.1 集合（Collections）

| 集合 | 用途 | 数量级 |
|---|---|---|
| `projects` | 作品集项目（一项目一页） | 9 条（现有 4 条占位 + 待拆） |
| `writing` | 写作（自传、散文、造物手记） | 3–6 条 |
| `pages` | 简历/联系等单页的正文块（可选：先沿用现有组件） | 2 |

### 2.2 Project 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | 文本 | 项目名（中文，专名不译） |
| `slug` | 文本 | URL 用；小写英文/拼音 |
| `period` | 文本 | 如 `2025.11–26.03`（内容事实，非页脚日期） |
| `role` | 文本 | 角色，如「产品负责人」「ID 设计 + PRD」 |
| `status` | 单选 | `latest` / `ongoing` / `archived`（Product.md §4a 状态标签制） |
| `accent` | 颜色 | 项目主色（A2 项目色，仅染本页强调细节） |
| `cover` | 图片 | 封面（海报墙用；Figma 导出优先） |
| `summary` | 文本 | 一句话摘要（海报展开态与目录页用） |
| `metrics` | 列表 | 对外可验证数字（KPI 行），如 `10 款产品` / `周期 −18%` |
| `tags` | 列表 | 如 `陶瓷 CMF` / `硬件` / `AIGC` |
| `body` | 块数组 | 正文（见 2.3） |
| `en` | 可选分组 | 英文版 title/summary/正文（V1 可空，缺省回落中文） |
| `ai-summary` | 文本 | 50 字「给 AI 的摘要」（白纸措辞终审），进 llms.txt 与 meta description（2026-09-13 AI Native 线增补） |

### 2.3 正文块类型（Body blocks）

| 块 | 用途 | 备注 |
|---|---|---|
| `p` 段落 | 正文 | 衬线；行高 1.75；不加自由颜色 |
| `h2` / `h3` | 小标题 | **h2 自动进目录**；h3 默认不进（层级控制） |
| `figure` | 单图 + 图注 | 图注必填（AI 精修时检查） |
| `gallery` | 图组（2/3 列） | 点击进灯箱 |
| `video` | 视频 | 封面图 + 点击播放 |
| `compare` | 前后对比（滑杆） | 过程证据（可选） |
| `quote` | 引用 | 素材原话（raw 里的可引用段） |
| `metrics` | 数字行 | 对外数字（Product.md §7.7） |
| `process` | 四问结构 | **问题 → 决策 → 取舍 → 结果**（PRD G2 叙事统一口径） |
| `note` | 旁注/待办 | 仅草稿可见（不随发布渲染） |

## 3. 文件与目录结构（提案）

```
web/
├─ content/
│  ├─ projects/
│  │  ├─ ruqieru-cuo.yaml（或 .mdoc，取决于 D2 选型）
│  │  └─ …
│  └─ writing/
├─ public/
│  └─ media/
│     └─ <slug>/            # 一项目一目录，避免同名冲突
│        ├─ cover.webp
│        ├─ 01-process.webp
│        └─ demo-short.mp4  # 短视频（受体积红线约束）
└─ src/
   ├─ components/blocks/    # 块组件（Figure/Gallery/Video/…）
   └─ lib/content.ts        # 读取与校验（schema 校验必做）
```

命名约定：媒体文件名 `两位序号-语义.webp`（`01-sketch.webp`）；项目目录用 slug。

## 4. 组件清单（块 → 组件映射）

| 块 | 组件 | 设计要求（承接 tokens/Design.md） |
|---|---|---|
| p | `<Prose>` | 衬线 16/1.75，墨色；段间距 16 |
| h2/h3 | `<SectionTitle>` | § 编号式（同简历页），下挂发丝线 |
| figure | `<Figure>` | 全栏宽；图注 mono 小字灰；加载占位防跳版 |
| gallery | `<Gallery>` | 2/3 列网格，发丝线分隔，点击灯箱 |
| video | `<Video>` | 封面 + 播放钮（墨黑圆形）；`preload=none` |
| compare | `<Compare>` | 滑杆手柄（墨黑），移动端可拖 |
| quote | `<Quote>` | 左侧竖线 + 衬线大字，署名 mono |
| metrics | `<Metrics>` | 数字（fs-d1）+ 标签（mono），横排或 2×2 |
| process | `<Process>` | 四段结构，编号 01–04，各段可含段落/图 |
| — | `<Toc>` | 左栏固定；h2 生成；滚动高亮（IntersectionObserver） |
| — | `<ProjectHeader>` | 封面大图 + 标题 + 角色 + 时期 + 状态标签 + 数字行 |

## 5. 目录（TOC）规则

- 来源：正文 `h2` 自动生成，不手写。
- 位置：桌面 ≥1280px 左栏固定（宽 200–240px），滚动高亮当前节；**≤1024px 收起为顶部可展开的目录条**。
- 高亮：`IntersectionObserver`（阈值取视口中带），不做 scroll 事件轮询（沿用"JS 显式驱动 + 降级"纪律）。
- 点击 = 锚点跳转（平滑滚动，尊重 reduced-motion）。
- 边界：h2 < 3 个时不渲染目录（避免空栏）。

## 6. 媒体处理

**图片**
- 源文件：任意常见格式，**单张源图 ≤ 2MB**（超限先压缩）。
- 构建期：输出 WebP（AVIF 可选）+ 多尺寸；列表/封面用缩略图，点开原图。
- 尺寸约定：正文图宽 ≤ 1440px；海报封面 1440×648（与现有海报墙比例一致）。
- 图注：`figure` 必填；无图注的图视为未完成（AI 精修检查项）。

**视频**
- 短视频（<15s、<20MB）：自托管 mp4/webm + 封面图 + `preload=none`。
- 长视频 / 高清：外链嵌入（B 站/YouTube），页面只放封面 + 播放入口（点击后再加载 iframe，避免首屏拖累）。
- **红线**：仓库内视频总量控制在几十 MB 量级；不得把长视频直接提交进 git（历史无法瘦身）。

## 7. 跳转与过渡

| 场景 | 实现 | 降级 |
|---|---|---|
| 海报墙 → 项目页 | 路由跳转 + View Transition 共享元素（封面图 morph 成页头大图） | 不支持 VT 的内核：直接跳转 |
| 简历 §4 条目 → 项目页 | 普通链接（hover 下划线，A5 链接规范） | — |
| 项目页目录 → 节 | 锚点平滑滚动 | reduced-motion：瞬时定位 |
| 项目页 → 下一个项目 | 页尾"下一个 →"（承接现有 `+`/`×` 交互语言） | — |
| 项目页 → 返回海报墙 | 头栏返回 + 浏览器后退 | — |

所有过渡时长沿用 tokens 动效档（≤600ms），不引入 CSS/JS 双驱动。

## 8. 编辑与协作工作流

```
白纸：Decap 后台新建项目 → 填字段 → 写正文 → 拖图/贴视频 → 保存（写回 git）
AI ：① 结构检查（标题层级/图注/媒体尺寸）
     ② 版式精修（对位、间距、图组节奏、暗色适配、移动端）
     ③ 本地构建 → 截图给白纸验收
白纸：验收 → 提意见（或直接改） → 定稿
AI ：push；若属系统性版式问题 → 沉淀进 tokens/组件，不改单页
```

分工边界：**内容与素材归白纸，版式规格与组件归 AI，数值归 tokens（改值回 Figma Variables）**。

## 9. 试点（第一个项目）

以 01「如切如磋，如琢如磨」或「臭氧催化氧化配套反应装置」为试点：
1. 安装并配置 Decap（本地后台可用）→ 定义 `projects` schema
2. 白纸在后台录入该项目（封面 + 摘要 + 数字 + 正文块）
3. AI 实现块组件（Figure/Gallery/Video/Metrics/Process）+ Toc + ProjectHeader
4. 接路由与跳转（海报墙、简历 §4 → 项目页）
5. AI 精修一轮 → 截图验收 → 白纸提意见
6. 定稿后把版式规格写入组件与本文档（升 v0.2）

**验收标准（试点通过条件）**
- 白纸全程未改代码即完成录入；从开始到本地预览 ≤ 30 分钟
- 页面含：目录 + ≥3 张图 + ≥1 个视频位 + 数字行 + 四问结构
- 黑夜模式、移动端 390px 不溢出；与简历页并排目检同一体系
- 首屏（本地）≤ 1.5s；仓库媒体增量 ≤ 20MB

## 10. 与既有文档的关系

| 文档 | 管什么 | 本文与它 |
|---|---|---|
| Product.md | 产品真相、内容边界（零假数据等） | 遵守；`metrics` 只收对外可验证数字 |
| Design.md | 决策宪法（黑白双层/字体/优先级） | 遵守；正文不开放自由颜色（强调=加粗+项目色） |
| Craft.md | 好坏的判断（HIG 索引 + 红线） | 组件设计需过其红线（动效预算/对比度等） |
| Templates.md | 页面模板（T2.x） | 本文补 T2.3 项目详情面的**内容与工程**实现 |
| tokens.css ↔ Figma Variables | 数值唯一源 | 组件只用变量，不硬写值 |

## 11. 风险与待观察

| 风险 | 影响 | 缓解 |
|---|---|---|
| Keystatic 维护放缓 | 编辑器停更 | 先 Decap；编辑器与内容解耦（换后台不动内容） |
| git 媒体体积膨胀 | 仓库变大、克隆变慢 | 体积红线 + 长视频外链 + 必要时考虑 Git LFS |
| 迁 Astro 的移植成本 | 一次性投入 | 翻页书逻辑照搬；外壳与内容层解耦，可分两步走 |
| 双驱动/旧内核问题复现 | 动效失效 | 沿用"JS 显式驱动 + 特征检测降级"纪律（已验证有效） |
