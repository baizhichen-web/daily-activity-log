# GitHub 项目管理试点与白纸学习路径

> 2026-10-06 白纸决策（原话）：「不迁移，但是如果有软件工程相关的项目，可以同步在github测试一下这套项目管理的方法，学习一下github」
> 本文 = 试点 playbook + 学习阶梯。复盘点：2026-12 上旬（满两个月）。

## 一、适用范围

- **飞书看板不变**：仍是工作空间 single source of truth，日巡/周审/导航体检三环不动。
- **触发条件**：代码类项目（当前候选：personal-website / baizhi-analyzer / dsh-*-bridge 插件）开工实现层工作。
- **GitHub 侧形态**：GitHub Issues 当工单（issue→分支→PR→review→merge），配 mattpocock 上游的 to-spec / to-tickets（tracker 选 GitHub）。
- **看板只留指针**：对应项目卡片「进度」字段加一行 GitHub 仓库/筛选视图链接，详情不抄过来。

## 二、两轨分工

| 进 GitHub Issues | 留飞书看板 |
| --- | --- |
| 代码任务的 spec/ticket/PR/review | 项目状态、里程碑、卡点方 |
| 代码决策 ADR（可逆性判断、为什么这么实现） | 跨项目依赖与管线关系 |
| commit/PR 的操作痕迹 | 方向性决策与白纸拍板记录 |
| （仅自己与 AI 可见，private 仓） | 与人协作、手机端、文档 |

## 三、试点操作流（第一个代码任务起照此跑）

1. **开工立项**：`gh issue create -R baizhichen-web/personal-website` 开一张 issue（标题=任务，正文=验收标准）。
2. **成 spec**：需要时对 issue 跑 to-spec（会话→spec，不盘问）；大改动先用 grill-with-docs 盘到共识再写。
3. **拆票**：to-tickets 把 spec 拆成 tracer-bullet 票据，阻塞边写进 issue（本地 tracker 模式下降级为 `wayfinder/` 或 issue 正文互引）。
4. **实现**：implement/implement-spec 按票做，TDD 在约定接缝处跑红绿；每票一个分支。
5. **收口**：code-review 双轴（仓库规范 × 对票忠实度）→ pr skill 写 PR 正文 → 白纸过目 → merge。
6. **回写**：merge 后看板卡片加一行 pointer（issue/PR 链接），**不在飞书复制内容**。

## 四、白纸学习阶梯（按需走到对应层即可）

- **L1 概念层（零门槛）**：issue ≈ 飞书看板的「任务」卡片，PR ≈ 「改完请检查」的申请，branch ≈ 平行草稿。概念 1:1 映射，看板经验直接迁移。
- **L2 操作层（第一个任务上手）**：自己走一遍 `gh issue create` → 分支名 `feat/xx` → 改动 → `gh pr create` → 看 diff 页 → merge。全程命令行，AI 在一旁报命令。
- **L3 流程层（试点中后期）**：GitHub Projects 看板视图（列=待办/进行中/完成，拖卡）——仅在 Issues 用顺之后作为视图增强，不替代飞书。
- **L4 纪律层（判断力）**：什么改动值得一张 issue、什么时候该 PR 而不是直接推、review 该看什么。这层靠试点两个月积累，AI 按 pr/code-review skill 的规则陪练。

## 五、gh 命令速查（本机已登录 baizhichen-web）

```bash
gh issue create -R baizhichen-web/personal-website --title "标题" --body "验收标准"
gh issue list -R baizhichen-web/personal-website            # 看工单
gh pr create --fill                                        # 起 PR
gh pr view --web                                           # 浏览器看 diff（读 code 最舒服的界面）
```

## 六、复盘条件（2026-12 上旬）

- 试点项目跑过 ≥3 个 issue→merge 完整循环；
- 白纸能独立完成 L2 操作；
- 判定：扩大（更多代码项目接入 / 上 Projects）或收掉（纯飞书+本地 markdown 票）。
